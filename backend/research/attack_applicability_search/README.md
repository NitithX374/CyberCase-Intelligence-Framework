# Cybersecurity NLP datasets for ATT&CK applicability

Checked: 2026-09-26. This is a literature and released-artifact audit, not a model evaluation.

The strongest classifier choice is **LADDER's existing relevant-sentence classification task**. The strongest extraction choice is **AnnoCTR's existing cybersecurity concept annotations and ATT&CK links**. Neither establishes a universal ground truth for whether arbitrary case material should use ATT&CK knowledge.

The shortlist preserves released labels. It does not convert technique labels, BIO tags, event types, retrieval relevance, or missing annotations into a new binary target. “Ready” means the native task has downloadable inputs and existing targets; it does not mean the original training software runs unchanged or that its dataset has an explicit reuse license.

## Important verification details

**LADDER.** The paper's relevant-sentence stage is already the binary task sought here, so using its labels does not invent a binarization. Its broader collection contains 150 reports about 36 malware, with 104/21/25 reports and 26/5/5 malware in the reported partitions. The classification CSVs are actually tab-separated. A separate native `ATK/O` phrase-extraction release has 1,144/308/348 sequences; it is an alternative task on the same corpus, not an independent dataset. [Paper](https://doi.org/10.1145/3607199.3607208), [author release](https://github.com/aiforsec/LADDER).

**AnnoCTR.** The expert cybersecurity layer covers 120 of the 400 reports. In the checked JSON, explicit `ce_tags` include CON, GROUP, MALWARE, TOOL, TACTIC and TECHNIQUE; implicit `ci_tags` include TECHNIQUE, TACTIC and a few GROUP annotations. Keep these supplied layers intact. The paper also studies separate four-way sentence classifiers for tactics and techniques: explicit, implicit, both, no mention. Creating a new four-way label column from spans would exceed this audit's strict ready-label criterion, so the recommendation is the native tagging/linking task. The supplied linking files with negatives contain 6,766/1,421/3,076 records, which are not sentence counts. [Paper](https://aclanthology.org/2024.lrec-main.103/), [data and licensing](https://github.com/boschresearch/anno-ctr-lrec-coling-2024).

**TRAM2.** Both checked copies of `multi_label.json` contain 19,178 rows. Some published studies describe older snapshots with 19,011 sentences/150 reports; do not combine those counts with this release. The native phrase task contains 5,089 single-label rows. The [annotation specification](https://github.com/center-for-threat-informed-defense/tram/wiki/Data-Annotation) documents span-overlap assignment and the selected label scope. The [training notebook](https://github.com/center-for-threat-informed-defense/tram/blob/main/model-development/train_multi_label.ipynb) splits rows, not reports. A newly documented split is an evaluation design choice, not new annotation, but it would not be an exact reproduction of an original frozen partition.

**MalwareTextDB.** Raw annotation distinguishes Subject/Object; the author-provided token files already supply Entity/Action/Modifier BIO labels. Keep that native task. The 6,966 sequence-block count should not be silently relabeled as the paper's 6,819 complete-sentence count. The original annotation study reports low agreement (kappa 0.36), a meaningful limitation for fine-grained spans. [Original paper](https://aclanthology.org/P17-1143/), [author archive](https://github.com/statnlp-research/statnlp-datasets/blob/master/dataset/MalwareTextDB-1.0.zip).

**CASIE.** The public release has article text and annotation JSON, so recrawling news sites or creating gold labels is unnecessary. Event realis distinguishes Actual, Generic, and Other; preserve it if evaluating that native task. The original training scripts request train/test file lists, but the checked repository did not supply a verifiable 900/100 membership manifest. Do not report an independently chosen partition as the original one. [Original paper](https://ojs.aaai.org/index.php/AAAI/article/view/6401), [release](https://github.com/Ebiquity/CASIE).

**Security-TTP-Mapping.** The Expert subset is the recommendation, not an unqualified mixture of all four sources. Live counts are Expert 697, TRAM derivative 4,797, Procedures 11,723, Derived Procedures 3,519. Derived Procedures uses BM25-selected source paragraphs and inherited procedure labels. The Expert test annotation was assisted by top-20 predictions from the authors' model; annotators were not required to add missing techniques. Consequently, unlisted labels can be incomplete rather than true negatives. [Original Findings paper](https://aclanthology.org/2024.findings-eacl.25/), [released files](https://huggingface.co/datasets/tumeteor/Security-TTP-Mapping/tree/main).

**Text2TTP.** The checked `load_annotated` reads `sentences.sanitized.csv`; both it and `sentences.csv` contain 2,017 manual and 1,522 TRAM examples, with no CISA or ESET category rows. The paper describes additional sources and 6,612 behaviors. The recommendation is limited to the downloaded annotated slice, not a claim that the complete published benchmark and split are released. [Paper](https://doi.org/10.1145/3634737.3645000), [loader](https://github.com/qcri/Text2TTP/blob/main/libs/resources.py), [data](https://github.com/qcri/Text2TTP/tree/main/data).

**CTI-ATE.** The 60 examples are malware descriptions paired with existing parent-technique targets. The paper's phrase “397 unique attack techniques” should not be copied as the number of distinct classes: the checked GT column contains 397 assignments across 115 distinct IDs. Its metric prose/table also disagree on micro/macro F1, so explicitly specify the automatic aggregation used. Other CTIBench tasks, such as multiple-choice CTI knowledge, are not behavior applicability tasks. [NeurIPS paper](https://papers.neurips.cc/paper_files/paper/2024/hash/5acd3c628aa1819fbf07c39ef73e7285-Abstract-Datasets_and_Benchmarks_Track.html), [native TSV](https://github.com/maveryn/cti-bench/blob/main/data/cti-ate.tsv).

### Search beyond the requested list

- **rcATT** provides report-level ATT&CK tactic/technique classification and public training files. It was not promoted above sentence/span tasks: document association is not localized adversarial behavior, and an unassigned technique is not an explicit no-ATT&CK judgment. [Author repository](https://github.com/vlegoy/rcATT).
- **TTPFShot** releases MITRE-derived sentence training data and CISA report evaluation artifacts. Its native task remains positive technique mapping; repository outputs and predictions should not be mistaken for an independently annotated sentence-negative benchmark. It was not recommended without a fully verified gold-label protocol. [Author repository](https://github.com/ait-cti/TTPFShot).
- **CyNER / CyBERTuned resources** were checked for related entity/event data and links. Generic CTI entity types do not establish adversarial action; a model repository is not evidence that a referenced CySecED corpus is downloadable. [CyNER](https://github.com/aiforsec/CyNER), [CyBERTuned](https://github.com/genesith/CyBERTuned).
- A 2026 preprint, **Evaluating Open-Source LLMs for Multi-Label ATT&CK Technique Classification on CTI Reports**, describes a promising sentence corpus with positive and negative examples. A working author data release was not verified, so it is not a recommendation. [Preprint](https://arxiv.org/abs/2606.18166).
- The **USENIX Security 2025 SoK** is useful literature positioning for TTP extraction and evaluation limitations. It is not a substitute for checking original artifacts or an authorization to adopt its preprocessing/label changes. [Paper](https://www.usenix.org/system/files/usenixsecurity25-buechel.pdf).

## Three recommendations

**A. Keep a classifier thesis: LADDER relevant-sentence classification.** Use its existing `text,label` files and original splits, and evaluate native positive-class precision/recall/F1. A defensible research question is “Can a model identify sentences describing attack patterns in CTI reports?” This directly connects to selecting evidence for ATT&CK-informed analysis without relabeling another task. Claiming universal ATT&CK applicability would go beyond the benchmark.

**B. Allow extraction/event detection: AnnoCTR native concept tagging, with optional ATT&CK linking.** The implicit layer addresses behavior described without explicitly naming an ATT&CK technique. Preserve all native tag types, use the released document split, and evaluate span F1. Add native link ranking only if needed. For an explicitly event-centric thesis, CASIE is the next choice, preserving all five event types and realis distinctions.

**C. Least combined methodology and coding effort: LADDER standalone sentence classification.** It already supplies the desired native target, negative labels, and fixed splits. No large ontology, span reconstruction, label mapping, or rejection threshold for a positive-only dataset is needed. Its main reservations are negative sampling, domain scope, and unspecified dataset license. If an explicit corpus license is essential, AnnoCTR is the cleaner licensed alternative but entails more extraction code; TRAM2 entails more taxonomy and evaluation caveats.

No shortlisted dataset proves a universal case-routing decision. Native classifier outputs, extracted spans, and retrieved techniques can support an applicability decision while retaining their original semantics. An automatically scored native benchmark does not establish deployment reliability on a different input distribution.

## Verification receipts and limits

- Original papers, repository trees, dataset cards, labels and representative annotation records were inspected. Primary downloads were exercised; counts came from parsers over released files, not search snippets.
- `verification.json` records parsed counts and checked repository revisions. `download_receipts.json` records fetched artifact URLs, byte sizes and hashes where available. Data and full papers remain in the local temporary audit cache; they are not redistributed in this repository.
- `citation_requests.json` and `citation_lock.json` separate scholarly metadata checks from claim-support records. All 13 recorded references resolved through Crossref or DataCite; the citation-lock check passed with `--main README.md`. This validates metadata and recorded support integrity, not experimental results. AnnoCTR is resolved by its arXiv DOI, not an assumed ACL DOI; direct arXiv API failures were resolved through registered DataCite identifiers.
- Model training, third-party code execution, result reproduction, license clearance, and pipeline integration were not performed. Difficulty and suitability rankings are reasoned judgments, not measured results.
- Unverified fields are explicitly unverified. A failed download is a failure to establish availability in this audit, not proof that no copy exists anywhere.
