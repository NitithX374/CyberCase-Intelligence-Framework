CyberCase Intelligence Framework เทียบกับ TechniqueRAG, H-TechniqueRAG และ TTP-LM บนชุดข้อมูลและตัวชี้วัดเดียวกัน
สาขาที่วัด: การระบุเทคนิค MITRE ATT&CK จากข้อความข่าวกรองภัยคุกคาม  ·  branch eval/published-baselines

ข้อค้นพบหลัก: ผลของการค้นคืนขึ้นอยู่กับว่าโมเดลกำเนิดข้อความรู้คำตอบอยู่ก่อนหรือไม่ เมื่อจับคู่กับโมเดลที่น่าจะเคยเห็นชุดทดสอบนี้มาก่อน การค้นคืนลด F1 ลง 0.068 แต่เมื่อจับคู่กับโมเดลที่ไม่มีความรู้เดิมนั้น การค้นคืนเพิ่ม F1 ขึ้น 0.269 หรือ +89% วัดบนตัวอย่างชุดเดียวกัน ด้วยการค้นคืนชุดเดียวกัน ต่างกันเพียงโมเดลกำเนิดข้อความ

นอกจากนี้ ทุก arm ของเราเป็น zero-shot ขณะที่ตัวเลขพาดหัวของ TechniqueRAG มาจากโมเดลที่ fine-tune แล้ว การเทียบที่เป็นธรรมจึงต้องเทียบกับแถวที่ไม่ fine-tune เช่นกัน

5. สรุปผล

ข้อค้นพบที่ 1 — ผลของการค้นคืนกลับทิศตามโมเดลที่จับคู่ด้วย

เป็นข้อค้นพบหลักของงานนี้ เดิมเมื่อวัดด้วย gpt-5.6-luna เพียงโมเดลเดียว ผลออกมาว่าการค้นคืนลดคะแนน ซึ่งเป็นข้อสรุปที่อธิบายได้ยาก เมื่อเพิ่มโมเดลที่สองเข้ามาในการทดลอง ภาพเปลี่ยนทั้งหมด

                 llm-only   rag-en    ผลของ retrieval
gpt-5.6-luna       0.693     0.625        -0.068

ตัวอย่างชุดเดียวกัน การค้นคืนชุดเดียวกัน prompt เดียวกัน ต่างกันเพียงโมเดลกำเนิดข้อความ ข้อสรุปที่ถูกต้องจึงไม่ใช่ “RAG ทำให้แย่ลง” แต่คือ การค้นคืนช่วยเมื่อโมเดลไม่รู้คำตอบ และรบกวนเมื่อโมเดลรู้ดีกว่าตัวค้นคืน ซึ่งงานนี้วัดได้ทั้งสองทิศทางในการทดลองเดียวกัน

ข้อค้นพบที่ 2 — หลักฐานสนับสนุนการปนเปื้อนของชุดทดสอบ

gpt-5.6-luna ตอบเองได้ 0.693 บนโจทย์ที่ qwen3.5-9b ทำได้ 0.302 — ต่างกัน 0.39 ซึ่งใหญ่เกินกว่าจะอธิบายด้วยขนาดโมเดลเพียงอย่างเดียว และยังสูงกว่าแถว GPT-4o zero-shot ของงานตีพิมพ์ (0.434) ถึง 26 จุด

procedure examples ของ MITRE เป็นข้อมูลสาธารณะ และ luna เป็นโมเดลรุ่นปี 2026 จึงมีความเป็นไปได้สูงว่าเคยเห็นชุดข้อมูลนี้ระหว่างการฝึก ข้อสังเกตนี้กระทบการตีความทุกงานที่วัดผลบน TRAM ด้วยโมเดลรุ่นใหม่ ไม่ใช่เฉพาะงานนี้

ข้อค้นพบที่ 3 — เทียบเท่าคู่เทียบที่คุมตัวแปร ด้วยองค์ประกอบที่เบากว่ามาก

ที่ระดับ technique ระบบนี้ทำได้ F1 0.571 เทียบกับ 0.546 ของ Ministral 8B (RAG) ซึ่งเป็นแถวที่คุมตัวแปรร่วมได้มากที่สุด: generator ขนาดใกล้เคียงกัน (9B เทียบ 8B) แบบสำเร็จรูปทั้งคู่ ไม่ fine-tune ทั้งคู่ ที่ระดับ sub-technique ได้ 0.424 เทียบกับ 0.377 (+12% เชิงสัมพัทธ์)

งานตีพิมพ์ระบุชัดว่าแถวดังกล่าวไม่ผ่านการ fine-tune — “GPT-4o (RAG), DeepSeek v3 (RAG), and Ministral 8B (RAG) use retrieved exemplars but receive no fine-tuning”

ผลเทียบเท่านี้ได้มาโดยใช้ re-ranker ขนาด 559M พารามิเตอร์ที่ประมวลผลในเครื่อง แทน DeepSeek v3 (671B total / 37B active) ที่ต้องเรียกผ่าน API ทุกครั้ง และไม่ต้องอาศัยตัวอย่างที่มีป้ายกำกับในโดเมนจำนวน 3,469 รายการ ซึ่งคลังค้นคืนของเขาพึ่งพา

ระยะห่างที่ระดับ technique คือ 0.025 ซึ่งแคบ จึงควรใช้คำว่า “เทียบเท่า” (comparable) มิใช่ “ดีกว่า” (superior)

ข้อค้นพบที่ 4 — ยังห่างจากตัวเลขพาดหัว และช่องว่างอธิบายได้

ระบบนี้ยังต่ำกว่า TechniqueRAG (0.740) อยู่ 0.169 ที่ระดับ technique ช่องว่างนี้สอดคล้องกับ ablation ในงานเดียวกัน ซึ่งรายงานว่าการ fine-tune generator เพียงอย่างเดียวให้ผลต่าง +0.194 บนโมเดลฐานและชุดค้นคืนเดิม (Ministral 8B RAG 0.546 → TechniqueRAG 0.740)

กล่าวคือ ปัจจัยเดียวที่งานตีพิมพ์ระบุว่ามีผลมากที่สุด มีขนาดใหญ่กว่าช่องว่างทั้งหมดของระบบนี้ และเป็นปัจจัยที่ระบบนี้ยังไม่ได้ใช้

ข้อค้นพบที่ 5 — ตัวค้นคืนอ่อนในฐานะตัวจัดอันดับ แต่แข็งในฐานะตัวสร้างตัวเลือก

P@1 อยู่ที่ 0.373 ต่ำกว่าทุก baseline ที่ตีพิมพ์ แต่เมื่อพิจารณาทั้งลิสต์ 20 อันดับ เฉลยปรากฏใน 83.3% ของตัวอย่าง (recall 0.805) ปัญหาจึงอยู่ที่การเรียงลำดับ ไม่ใช่การค้นไม่เจอ ซึ่งอธิบายว่าเหตุใดการเพิ่ม LLM เข้ามาเลือกจากตัวเลือกเหล่านั้นจึงยกคะแนนได้ถึง +89%

ข้อค้นพบที่ 6 — คอขวดอยู่ที่ฟังก์ชันจัดอันดับ ไม่ใช่สิ่งที่ป้อนให้มัน

6. ข้อจำกัดของการทดลองนี้

  • ตัวเลขทั้งหมดมาจาก arm ที่เป็น ablation ยังไม่ใช่ pipeline ที่ให้บริการจริง arm agent พัฒนาเสร็จแล้วแต่ยังไม่ได้รัน
  • วัดบนชุด TRAM เท่านั้น ยังไม่ได้วัด Expert (multi-label) และ Procedures
  • ความสามารถหลายภาษาและการใช้กราฟความสัมพันธ์ ยังไม่ได้ประเมิน — ชุดทดสอบนี้เป็นภาษาอังกฤษ และ input สั้นเกินกว่าจะมีความสัมพันธ์ระหว่าง entity ให้ใช้ ทั้งสองข้อจึงไม่ควรถูกอ้างเป็นผลของงานนี้
  • การเทียบ rag-en กับแถว RAG ของงานตีพิมพ์ ปนตัวแปรทั้งตัวค้นคืนและคลังข้อมูล แยกจากกันไม่ได้
  • MRR เทียบกับต้นทางไม่ได้ ด้วยเหตุผลในหัวข้อ 2.2
  • ข้อสรุปเรื่องการปนเปื้อนเป็นการอนุมานจากคะแนน มิใช่การตรวจสอบชุดข้อมูลฝึกของโมเดลโดยตรง
