## 1. คำถามที่ต้องการตอบ

การทดลองรอบก่อนพบว่า `hyde_fuse_sub` เพิ่มการค้นคืนขั้นตอนที่สำนวนแค่บรรยายพฤติกรรมได้อย่างมีนัยสำคัญ (StepCoverage@10 +.057, p<.001) แต่รอบนั้นวัด**เฉพาะส่วนค้นคืน** รอบนี้จึงถามต่อว่า เมื่อใส่ HyDE เข้าไปใน agent ตัวจริงที่ใช้งาน **คำตอบสุดท้ายดีขึ้นจริงหรือไม่ และยังอ้างอิงจาก context (grounded) อยู่หรือเปล่า**

## 2. วิธีการ

### 2.1 สิ่งที่ต่อเข้า agent

- **Flag `HYDE_RETRIEVAL`** ใน `config.py` ค่าเริ่มต้นปิด
- **`_node_retrieve` ใน `agent_graph.py`:** เมื่อเปิด flag แต่ละ sub-query ที่ decomposer แยกได้จะค้นทั้งด้วยตัวเองและด้วย HyDE entry แล้วรวมผล ส่วน reranker ยังให้คะแนนเทียบกับ sub-query ส่วนช่องที่ค้นด้วยทั้งสำนวนและ query ที่ evaluator เขียนใหม่ตอน broaden ไม่ใช้ HyDE
- **ต้นทุน:** เพิ่ม LLM call หนึ่งครั้งต่อการค้นหนึ่งรอบ

### 2.2 Arm ที่เปรียบเทียบ

ทั้งสอง arm รัน agent ตัวจริงครบทุก node (route → decompose → retrieve → evaluate → broaden → reasoning) ผ่าน `graph.stream`

| Arm | รายละเอียด |
|---|---|
| **P** production | HyDE ปิด คือระบบที่ใช้งานอยู่ตอนนี้ |
| **H** + HyDE | HyDE เปิด (`fuse_sub`) และ**ใช้ sub-query ชุดเดียวกับ P** |

เหตุผลที่ H ใช้ sub-query ชุดเดียวกับ P: decomposer ไม่ deterministic แม้ตั้ง temperature 0 ถ้าให้ H แยกใหม่เอง sub-query จะเปลี่ยนไปพร้อมกับ HyDE แล้วจะแยกไม่ออกว่าผลต่างมาจากอะไร

ส่วนขั้นหลังจากนั้น (evaluator, broaden, reasoning) รันจริงทั้งสอง arm เพราะเป็นผลที่ต้องการวัด ใน 100 เคส H ใช้ sub-query ชุดเดิมของ P 112 จาก 120 รอบการค้น อีก 8 รอบเป็น broaden รอบที่ P ไม่ได้ทำ จึงแยกใหม่จริง

### 2.3 Metric

- **F1 / Precision / Recall:** เทียบ technique ID ที่คำตอบอ้างถึงกับ gold ที่นักวิเคราะห์กำหนด (roll up เป็น parent technique)
- **Step recall:** สัดส่วนขั้นตอนการโจมตีที่คำตอบอ้าง technique ถูก แยกเป็นขั้นตอนที่บรรยายพฤติกรรมกับขั้นตอนที่ระบุชื่อ
- **Context gold recall:** สัดส่วน gold technique ที่ปรากฏใน context ที่ใช้เขียนคำตอบ
- **Grounding:** สัดส่วน ID ที่คำตอบอ้าง แต่ไม่มีอยู่ใน context
- **สถิติ:** ผลต่างแบบ paired ต่อเคส, 95% CI จาก bootstrap 10,000 รอบ, p-value จาก Wilcoxon signed-rank

## 4. การตีความ

1. **ผลดีของ HyDE ในการค้นคืนไม่ส่งต่อไปถึงคำตอบ** F1 เท่าเดิม (−.007, ไม่มีนัยสำคัญ) HyDE ยังเพิ่ม gold เข้า context ได้นิดหน่อย (+.019) และเพิ่ม recall ของคำตอบเล็กน้อย (+.013) แต่ precision ลดลง (−.021) จนหักล้างกันพอดี
2. **ทำไมผลในการค้นคืนหายไป:** การทดลองรอบก่อนวัดเฉพาะรายการ vector ที่ K ≤ 10 แต่ agent ตัวจริงมี context ใหญ่กว่า (15 vector hits + 8 subgraph จาก graph expansion) และมีรอบ broaden ด้วย ระบบ production จึงมี gold อยู่ใน context แล้วถึง **86%** HyDE เหลือพื้นที่ให้เติมไม่มาก
3. **คอขวดตอนนี้อยู่ที่ขั้น reasoning ไม่ใช่การค้นคืน** ใน P:
   - context มี gold .862 แต่คำตอบดึงออกมาได้ .815
   - precision แค่ .676 คือประมาณ 1 ใน 3 ของ ID ที่คำตอบอ้างไม่ใช่ gold

   การปรับการค้นคืนเพิ่มอีกจึงได้ผลน้อย จุดที่ควรปรับต่อคือขั้นที่ LLM เลือกว่าจะอ้าง technique ไหน
4. **Grounding ไม่เสีย** ID ที่อ้างแต่ไม่อยู่ใน context ยังต่ำมากทั้งสอง arm (.2–.5%) ความกังวลว่าชื่อที่ HyDE เดาจะทำให้คำตอบอ้างสิ่งที่ไม่มีหลักฐานไม่เกิดขึ้น เพราะใน `fuse_sub` reranker ยังตัดสินด้วยถ้อยคำในสำนวน
5. **ต้นทุนเพิ่มจริง** ช้าลงประมาณ 20 วินาทีต่อเคส (+45%) และแพงขึ้น 13% ตัวเลข latency ของ H ต่ำกว่าความจริงด้วย เพราะไม่ได้นับเวลา decompose ที่ใช้ชุดเดิมจาก P
6. **ความแปรปรวนของขั้น reasoning สูง**
   - HyDE ทำให้ context เปลี่ยนใน 96/100 เคส ส่วนใหญ่แค่ลำดับหรือเอกสารที่ได้ต่างไป แต่ gold ที่อยู่ใน context เปลี่ยนจริงแค่ 15 เคส (ดีขึ้น 11 แย่ลง 4)
   - ใน 4 เคสที่ context ของสอง arm **เหมือนกันทุกตัวอักษร** คำตอบยังต่างกันทั้ง 4 เคส แปลว่า LLM ในขั้น reasoning ไม่ deterministic แม้ temperature 0
   - F1 ที่ดีขึ้น 25 เคสและแย่ลง 29 เคสจึงน่าจะมี noise ของ LLM ปนอยู่มาก ไม่ใช่ผลของ HyDE ล้วน ๆ

## 5. ข้อสรุปและข้อเสนอ

- **ไม่เปิด HyDE ใน production** ให้ `HYDE_RETRIEVAL` คงค่า `false` เพราะไม่เพิ่มคุณภาพคำตอบ แต่ช้าลงและแพงขึ้น
- **เก็บโค้ดไว้** เพราะอยู่หลัง flag ไม่กระทบระบบ และใช้ทดลองซ้ำได้ถ้าเปลี่ยนโมเดลหรือ context budget
- **สำหรับวิทยานิพนธ์ ผลนี้มีค่า** แสดงให้เห็นว่า:
  - **(ก)** HyDE เพิ่มการค้นคืนอย่างมีนัยสำคัญเมื่อวัดเฉพาะส่วนค้นคืน
  - **(ข)** แต่ไม่ส่งต่อถึงคำตอบ เพราะระบบ production (decompose + quota + graph expansion) ครอบคลุม gold ใน context ได้ 86% แล้ว
  - **(ค)** คอขวดจึงย้ายไปอยู่ที่ขั้น reasoning

  ตรงกับหลักที่ตั้งไว้ว่าต้องวัดผ่าน agent ตัวจริงก่อนสรุป เพราะผลที่ดีในระดับ component อาจไม่ส่งต่อถึงผลลัพธ์สุดท้าย

### ขั้นต่อไปที่แนะนำ

1. **ปรับ precision ของขั้น reasoning** เช่น ให้ LLM อ้าง technique เฉพาะที่มีหลักฐานในสำนวนชัดเจน หรือใช้ threshold ของ MITRE table ช่วยกรอง
2. **วัด noise floor** โดยรัน P ซ้ำอีกรอบกับ context เดิม เพื่อรู้ว่าผลต่าง F1 ระดับไหนที่เกิดจากความแปรปรวนของ LLM ล้วน ๆ ค่า LLM ประมาณ $0.5
